# 自律激励系统 · 需求文档（v0.3 · 定稿）

> 一个小范围使用、**手机 + 电脑都能用**的在线系统。核心理念：用一套「虚拟人民币经济」逼自己每天完成任务——
> 系统每天自动扣钱让你"负债"，你必须靠完成任务把财富从负变正，
> 完成必做事项还能换取"无愧疚消费券"，并和朋友比拼财富 / 任务量 / 学习时长。

---

## 一、产品定位

- **使用人群**：自己 + 小范围好友（小圈子，非公开）
- **形态**：在线 Web 系统，**响应式设计，手机和电脑都要适配好**（手机为主要使用场景）
- **一句话**：把"自律"变成一个有货币、有奖惩、有排名的游戏。

---

## 二、核心概念

| 概念                 | 说明                                                           |
| -------------------- | -------------------------------------------------------------- |
| **总财富**     | 每个用户的虚拟人民币余额，可正可负                             |
| **每日扣款**   | 每天**凌晨 00:00 自动扣 300 元**，制造"负债压力"         |
| **任务奖励**   | 完成任务获得虚拟人民币，金额由 AI 评定                         |
| **兑换券**     | 完成当天全部「必做事项」后获得 1 张，可"无愧疚"地玩游戏/出去玩 |
| **学习计时器** | 学习时开计时器并填入正在做的任务，结束后结算收益并存档         |
| **排行榜**     | 按财富 / 完成任务数 / 学习时长 排名                            |

## 三、功能需求

### 1. 任务系统（日历清单）

- **必做事项（每日固定）**
  - 每天都会出现，是雷打不动的任务
  - **数量和内容由用户自己定义**（自己设置一份每日固定清单）
  - 当天全部完成 → 触发「兑换券」奖励（+1 张）
- **自定义事项**
  - 用户随时新增的临时任务
- 任务字段：名称、类型（必做/自定义）、是否完成、奖励金额、所属日期、（可选）学习时长
- 以**日历视图**或**当日清单**展示，可勾选完成

### 2. AI 奖励定价

- 用户创建/录入任务时，由 **AI（通义千问）根据任务难度、价值、耗时**自动给出奖励金额
- 输出：奖励金额（虚拟人民币）
- **定价基准（喂给 AI 的标准）**：让用户**认真过完充实的一天 ≈ 累计赚 500 元**
  - 每日扣 300，所以认真一天净结余约 **+200**；划水的一天则会被扣成负数
  - 大致量级参考（由 AI 严格把握，不是死板公式）：
    - 普通小任务（洗碗、背单词）≈ 20~40
    - 中等任务 / 学习约 1 小时 ≈ 60~120
    - 硬核任务 / 高强度学习 1 小时 ≈ 120~200
- **严格判断**：AI 要结合任务的真实价值和强度认真评估，不能随意放水
- 需兜底：AI 不可用时给一个默认金额，不阻断流程

### 3. 学习计时器 ⭐（核心交互）

> 这是学习时长的记录方式，也是数据面板的主要数据来源。

> **重要：计时器的任务 = 待办清单里的任务，是同一个。计时本身就是"完成任务"的方式，奖励只结算一次，不存在双重领钱。**

- **开始**：点击开始计时，指定正在做的任务，**两种方式二选一**：
  - 从自己已有的待办事项中**选择**一个；或
  - 直接**输入文本新建** → 系统**自动创建**这个任务（默认它正在进行）
- **进行中**：实时显示已计时时长
  - **采用「记录开始时间戳、结束时算差值」的方式** → 手机锁屏 / 切后台都能继续计时，时长准确
- **结束**：停止计时
  - **AI 根据「任务 + 学习时长」严格结算收益**（加到财富里）
  - **该任务同时标记为已完成**（计时即完成，不再重复发奖）
  - 把本次记录**存档**：任务名、开始/结束时间、总时长、获得收益
- 这些存档数据后续用于：
  - 个人**数据面板**（每日/每周学习时长、收益趋势等）
  - 排行榜的"学习时长"维度

### 4. 虚拟货币经济

- **完成任务 / 计时结束** → 财富 +奖励金额
- **每日扣款** → 每天 **凌晨 00:00 扣 300 元**（定时任务自动执行）
- **财富可以无限为负，暂不设下限，也暂无额外惩罚**
- 目标：让你必须主动完成任务，才能把财富维持在正数
- 需要一份**财富流水记录**（每笔加/减的时间、原因、金额）

### 5. 兑换券系统

- 触发条件：**当天所有必做事项全部完成** → 获得 **1 张**
- **永不过期**，可累积
- 用途：纯粹的"心理许可"——拿着券去玩游戏、出去玩，不带愧疚感（系统内无抵扣等实际作用）
- 需记录：拥有数量、获取记录、使用记录（手动"使用"一张）

### 6. 数据面板（个人统计）

- 当前财富、兑换券数量
- 学习时长统计（今日/本周/累计）+ 趋势图
- 收益统计（来自任务完成 + 计时结算）
- 任务完成情况（完成率等）

### 7. 排行榜

- **所有用户共用一个总榜**（不分组）
- 三个维度排名：
  1. **总财富**
  2. **完成任务数量**（可分今日/本周/总计）
  3. **累计学习时长**
- 展示每位用户的头像/昵称 + 对应指标

### 8. 用户系统

- **登录方式：账号密码，自己注册**
- 个人资料：昵称、头像（系统内自己设置）
- 个人数据：当前财富、兑换券数量、历史统计

## 四、已确定的业务规则 ✅

| 规则              | 决定                                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| 每日扣款金额      | **300 元**                                                                    |
| 每日扣款时间      | **每天凌晨 00:00**                                                            |
| 必做事项数量/内容 | **用户自己定义**（自定义每日固定清单）                                        |

| 兑换券过期        | **永不过期**，可累积                                                          |
| 兑换券作用        | 仅心理许可，无系统内抵扣等功能                                                      |
| 学习时长记录      | **计时器**：选已有待办 / 输文本新建 → 锁屏继续计时 → 结束 AI 结算收益并存档 |
| 财富负数下限      | **暂不设限，无额外惩罚**                                                      |
| 平台适配          | **响应式，手机 + 电脑都要适配**                                               |
| AI 接口           | **通义千问（DashScope / Qwen）**                                              |
| 排行榜            | **所有用户共用一个总榜**                                                      |
| 登录方式          | **账号密码，自己注册**（暂不做微信登录）                                      |
| AI 定价基准       | **认真过完充实一天 ≈ 赚 500 元**（扣 300 后净约 +200）                       |
| 学习计时收益      | **AI 按「任务+时长」严格判断**，非固定时薪                                    |
| 任务 vs 计时      | **同一个任务**：计时即完成，奖励只结算一次，无双领                            |
| 防作弊            | **不做，纯靠自觉**（熟人小圈子）                                              |

## 六、建议的开发优先级（MVP）

> 先做能跑起来、自己每天能用的最小版本，再逐步加。手机适配从第一阶段就要做好。

**第一阶段（MVP — 自己单人能用）**

1. 用户登录
2. 每日任务清单（必做模板 + 自定义，可勾选）
3. 完成任务加钱、每天凌晨 00:00 定时扣 300
4. 财富余额 + 流水展示
5. **响应式布局（手机优先）**

**第二阶段（核心激励闭环）**
6. 学习计时器 + AI 结算 + 存档
7. AI 自动定价
8. 兑换券系统
9. 个人数据面板

**第三阶段（社交）**
10. 多人 + 三维排行榜

## 七、技术栈（已确定）

- **前端**：React + Vite，**响应式 / 移动优先**（可加 PWA，让手机"添加到主屏幕"像 App 一样用）
- **后端 + 数据库**：**Supabase**
  - Auth：账号密码注册登录（自带）
  - Database：Postgres（存任务、流水、计时记录、兑换券等）
  - Edge Functions：放需要保密 Key 的逻辑（调通义）
- **定时扣款**：Supabase 定时任务（pg_cron / scheduled function），每天**凌晨 00:00** 给所有用户扣 300
- **AI 定价/结算**：在 Edge Function 里调**通义千问 DashScope（Qwen）**
  - Key 存 Supabase 的环境变量（`DASHSCOPE_API_KEY`），**前端永不接触**
  - AI 不可用时给默认金额兜底
- **部署**：前端挂 Vercel，后端用 Supabase 托管（都有免费额度，够小圈子用）
